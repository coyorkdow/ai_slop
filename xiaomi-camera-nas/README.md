# 远程下载录像

访问地址：`http://<机器名>.<tailnet>.ts.net/`

手机或远程电脑安装 Tailscale，登录与这台 Mac 相同的账号并连接，然后打开上述完整域名。服务仅在 Tailscale 私人网络内提供访问。

点击录像下载压缩版，再用本地播放器打开。页面也提供“下载原文件”链接（`?original=1`）。压缩版为最大 1280×720、HEVC（H.265）、15 帧/秒、视频码率上限 400 kbps、AAC 音频 32 kbps。400 kbps 是上限：画面静止时编码器只用约 180 kbps，画面变化多时才接近上限。降低分辨率、帧率和码率会损失细节；原录像始终保留。实测 60 秒夜间样片从 4.5 MiB 降到 1.6 MiB，完整文件大小随内容变化。

目录会把文件名中的两个 `yyyymmddhhmmss` 时间戳显示为易读的起止时间；原文件名仍显示在时间下方，下载时保持原有文件名。

目录按录像开始时间分为年 / 月 / 日虚拟文件夹（显示为 `2026` › `October` › `Oct 29 (Thu)`）（跨天录像归入开始那天），顶部有路径导航和“上级”按钮。目录不依赖 NAS 上的真实文件夹（摄像头曾把重传的录像写进多套一层的同名子目录）：服务递归收集录像目录下的所有视频，只按文件名中的时间戳归类。虚拟文件夹只是查询参数（如 `/?date=2026-10-29`），不改动磁盘上的目录结构；访问真实文件夹的旧链接会跳转到对应的虚拟文件夹。文件名中没有时间戳的视频直接显示在第一层；同一文件名出现在多个真实文件夹时，各自显示所在位置。

## 删除录像

每段录像下方有“删除原始视频”和“删除压缩版”按钮（只显示当前存在的那一份），点击后浏览器会先弹出确认框。

- **删除压缩版、保留原始视频**：同时删除该录像的全部压缩副本、清单、画面变化索引和关键帧缩略图，回到未压缩状态；后台按正常流程重新压缩，发布后重新分析画面变化。
- **删除原始视频、保留压缩版**：只删除 NAS 上的原文件，目录显示“源录像已删除，仅保留压缩版”，压缩版和索引仍可用。
- **两份都删除**（无论先删哪一份）：删除本地关于该录像的所有记录（清单、压缩副本、索引、缩略图），录像从目录中消失。

进入某一天的文件夹后，每段录像前有勾选框，顶部有“全选”“全不选”“删除选中的原始视频”“删除选中的压缩版”。批量删除对每段勾选的录像执行与单个按钮相同的操作；所选录像中没有对应文件的会被跳过，完成后页面顶部显示删除和跳过的数量。年、月文件夹不提供勾选。

删除不可恢复。压缩进行中删除原始视频会取消本次压缩；正在分析画面变化时删除压缩版，分析结果会被丢弃。摄像头之后如果重新上传同名录像，会作为新录像处理。

## 画面变化索引

检测步骤、阈值、索引格式和已知局限详见 [MOTION_DETECTION.md](MOTION_DETECTION.md)。

压缩版发布后，后台使用 FFmpeg 每秒抽取 2 张 320×180 灰度图，并用 OpenCV 比较相隔约 2 秒的画面，做降噪、光照补偿及局部运动检测，以便发现夜视画面中缓慢移动的小动物。持续变化合并为事件；目录按录像显示事件数量，点击“展开关键帧”可查看缩略图和录像内时间，下载后可按该时间在播放器中定位。算法用于快速筛选，可能漏掉短暂或很小的活动，也可能把局部光影变化标为事件。

索引与每份压缩文件绑定，重新压缩会重建索引；旧压缩版保留期间仍显示对应旧索引。分析失败时目录显示提示，录像下载不受影响。现有压缩版在服务重启后会逐个补建索引，长录像可能需要等待；检测结果保存在状态目录的 `playback/` 中。运行服务的 Python 3.8 环境需要 `numpy==1.24.4` 和 `opencv-python-headless==4.8.1.78`。

## 写入检测与压缩

1. 每 15 秒观察文件大小、mtime、ctime、inode 和设备号。必须连续观察 **5 分钟无变化**才排队压缩；每次变化重新计时。重启后未处理文件也重新观察完整的 5 分钟。
2. 创建私有临时快照，复制时计算 MD5，并检查路径和已打开文件的状态。复制完成后独立读取源文件计算 MD5，与快照比对。FFmpeg 只读取快照。
3. 一次只压缩一个文件，使用 Mac VideoToolbox 编码器和较低进程优先级。压缩中约每 2 秒检查源文件状态；若再次写入，终止压缩并清理临时结果，重新等待。
4. 压缩完成后再次核对源文件 MD5，验证输出时长、末尾解码和体积，再原子更新清单。清单记录 `source_md5`、源文件状态、输出文件名、大小和时长。

压缩完成后的一小时内，源文件变化仍会使旧压缩版失效，待源文件稳定 5 分钟后重新压缩。**一小时后才发生变化**时，继续提供旧压缩版，不自动重压缩；目录显示“源录像发生变化”的提示和“重新压缩”按钮。点击按钮后仍须观察完整的 5 分钟安静期；新版压缩成功发布前，旧版一直可下载。重新压缩失败时保留旧版，并约 5 分钟后重试。按源文件最后修改时间判断变化发生在一小时内还是之后；旧清单没有完成时间字段时，以清单文件的修改时间为完成时间。已经在一小时内判定失效的副本，不会因为后来跨过一小时而重新变为可用。

源录像被删除时，目录单独标示“源录像已删除”，只提供已有压缩版下载，不提供原文件下载或重新压缩按钮。清单记录源录像的相对路径；服务启动时会为仍有源录像的旧清单补齐路径，因此升级后应先重启服务，再删除源录像。旧清单如果在升级前已经失去源录像，无法从哈希文件名恢复路径，也就无法显示在目录中。

若压缩命令失败、原视频无法解析、输出时长不符或压缩结果无效，临时快照和未发布的文件会被清理，日志记录错误；页面显示“压缩失败，稍后重试”，原文件下载链接仍可用。后台约 5 分钟后会对同一源文件再试；若源文件持续损坏，重试会持续发生。已有的压缩文件不会因一次失败而从磁盘删除；手动重压缩晚于一小时发生的变化时，旧版仍可下载。一小时内源文件已变化时不会继续提供该旧版本。

普通复制、MD5 和本服务的进程锁不能与不配合的 NAS 写入端建立严格的原子事务。这是乐观校验：发现并发写入或内容不一致就放弃结果并重试。5 分钟安静期也不能保证未来不再补写。MD5 用于检测非恶意文件变化，不作为防篡改认证。

## 下载一致性

- 下载开始前重新计算尚存在的源文件 MD5。一小时内的变化会让旧压缩结果失效，返回 HTTP 503 的等待页面并重新开始 5 分钟观察；一小时后的变化保留旧压缩版，目录展示提示和手动重压缩按钮。源文件已删除时，仍可下载清单索引到的旧压缩版。
- 校验通过后打开不可变的压缩文件，整个下载读取同一个文件句柄。源录像此后发生变化或生成新压缩版，也不会混入本次下载。已经开始的下载可能是旧快照，但文件内部保持一致。
- 响应使用 `Content-Disposition: attachment`。不提供浏览器在线播放、版本重定向或断点续传；忽略 Range，始终返回 HTTP 200 的完整文件，下载失败后重新下载，避免新旧版本拼接。
- 目录列表只检查元数据，不对所有录像计算 MD5。实测本机校验 128 MiB 文件约需 0.25 秒，每次下载开始时会有这项开销。

## 文件与运行

- 原录像：`/Users/Shared/XiaomiCamera`，由环境变量 `XIAOMI_CAMERA_ROOT` 指定（默认即此路径）
- 代码：`~/github/ai_slop/xiaomi-camera-nas/`，与录像目录分离
- 下载服务：`server.py`，本机监听 `127.0.0.1:8765`
- 压缩与一致性检查：`playback.py`
- 无写入等待时间：`SETTLE_SECONDS = 5 * 60`
- 运行时产生的文件全部在 `XIAOMI_CAMERA_STATE`，默认 `/Users/Shared/XiaomiCamera/.remote-access/var/`（录像目录下的隐藏目录，不会出现在下载目录中），可随时删除（删除压缩缓存后会重新压缩）：
  - 压缩副本、清单、锁和临时文件：`var/playback/`
  - 日志：`var/log/server.log`、`var/log/server-error.log`、`var/log/downloads.jsonl`（及轮转备份 `.1`–`.3`）
- 自启动：`~/Library/LaunchAgents/com.xiaomicamera.video-server.plist`，内容与本目录的同名文件一致；修改后执行 `cp com.xiaomicamera.video-server.plist ~/Library/LaunchAgents/ && launchctl bootout gui/501/com.xiaomicamera.video-server; launchctl bootstrap gui/501 ~/Library/LaunchAgents/com.xiaomicamera.video-server.plist`

总磁盘占用仍包含原文件和压缩副本；处理期间额外需要一份源文件快照及正在生成的压缩文件。正常完成或取消会清理快照，成功发布会删除该录像被替换的旧播放副本。异常断电可能留下临时文件，暂不自动清理已删除原录像对应的副本。

使用本机 Elmedia Player 内的 `/Applications/Elmedia Player.app/Contents/Resources/ffmpeg`，请保留此应用；也可将带 VideoToolbox 编码器的 FFmpeg 安装到服务的 PATH 中。

Mac 必须开机、联网、保持唤醒并连接 Tailscale。录像服务在安装 LaunchAgent 的用户登录 macOS 后自动启动，退出该用户会停止服务。

服务已启用下载版和诊断日志。以后修改代码需重启后生效；请在没有下载或压缩任务时执行：

```sh
launchctl kickstart -k gui/501/com.xiaomicamera.video-server
```

## 下载诊断日志

独立日志：`/Users/Shared/XiaomiCamera/.remote-access/var/log/downloads.jsonl`，每行一个 JSON 对象。单文件最多约 5 MiB，保留 3 份轮转备份，时间采用 UTC（北京时间加 8 小时）。

```sh
tail -f /Users/Shared/XiaomiCamera/.remote-access/var/log/downloads.jsonl
```

- `request_id`：关联同一次请求的开始、进度和结束；响应也带 `X-Request-ID`。
- `event`：`download_start`、`download_progress`、`request_end`、`server_start`。
- `verify_seconds`：压缩副本有效性检查耗时，包含源文件 MD5 校验。
- `headers_seconds`：从处理请求到响应头发送结束的时间。
- `file_bytes_expected`、`file_bytes_sent`：视频预期字节数和成功交给 socket 的字节数，不包括响应头、目录页面。
- `transfer_seconds`、`total_seconds`：视频发送阶段和请求处理总耗时。
- `send_MiB_s`：发送阶段累计平均速度，单位 MiB/s，包含磁盘读取和 socket 等待。
- `outcome`：`sent_to_proxy` 已全部发送给下游 socket；`disconnected` 下游连接断开；`not_ready` 视频尚未就绪；`source_truncated` 读取提前结束；`error` 出错；`head_only` 仅查询响应头。

在持续完成写入时，每约 5 秒记录一次进度；如果 socket 写入阻塞，进度日志也会暂停。中断时当前失败写入的块可能已有部分送出，`file_bytes_sent` 是保守计数。进程被强制终止或断电时可能只有开始日志，没有结束日志。

**这些指标不能证明远端下载完成。** Tailscale Serve 通过本机回环代理访问服务，`peer` 通常是 `127.0.0.1`，发送速度包含代理缓冲影响，并非实际公网或手机落盘速度。远端实际测速仍需客户端的下载耗时和字节数；连接是否直连或中继可在远端下载时运行：

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale status
```

日志不记录 Cookie、授权头或完整查询参数，仅记录路径和是否下载原文件。

运行测试：

```sh
python3 test_playback.py
```

测试覆盖 5 分钟观察、写入导致重新计时、复制/压缩期间继续写入、元数据相同而 MD5 不同、一小时内外的变化、手动重压缩失败后旧版仍可下载、源文件删除后的目录和下载、旧清单兼容、压缩失败及截断结果不可发布、处理中止、附件下载，以及下载中替换压缩文件仍读取同一份内容。

停止远程访问：

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --http=80 off
```

恢复远程访问：

```sh
/Applications/Tailscale.app/Contents/MacOS/Tailscale serve --bg --http=80 http://127.0.0.1:8765
```
